## 2. Answers to critical checks

1. **Does the Excel P&L upload parse revenue/expense lines into a structured preview? — NO.**
   `uploadReport` only stores the file (`status: 'stored'` unconditionally — ReportController.php:240) with no format validation. `preview` flattens the sheet into generic `{label, value, type, header}` cells (`matrixToRows`, ReportController.php:413-437). There is no revenue-by-channel section (no aggregator split), no operating-expense lines, no net profit or margin computed from the upload, and no per-restaurant/month persisted P&L. RPT-1 steps ②③ are cosmetic only. (`ReportService::salesByChannel` computes channels incl. delivery apps but from operations, not from the uploaded ERP Excel.)

2. **Does send support channel + format + cover message + bulk to owners? — PARTIALLY.**
   Bulk: yes — omitting `restaurantIds` targets all active restaurants in the tenant (ReportController.php:160-164), one `ReportDistribution` per restaurant inside `DB::transaction` (170-201). Channel: `channels[]` validated `in:email,inApp` (148-149) but **email is never sent** (no Mail/mailable anywhere in the flow) and the in-app notification is pushed to the **sender's own user id**, not to brand owners (184-193). Format: **no PDF/Excel/both parameter exists**; no attachment is generated or linked. Cover message: **no field at all**. Owner emails exist read-only in `status()` output (`AsabBrand.owner_email`, 293-310) but are never used as recipients. RPT-3 and BRO-1.2 are therefore unmet.

3. **Does status flip to sent + download? — SENT YES, DOWNLOAD NO (admin surface).**
   After send, `ReportDistribution.sent=true`/`sent_at` is set (172-182) and `GET …/status` reports per-restaurant `sent/sentDate` + summary (296-330) — ✅. `viewed` can never become true (no code writes `viewed_at`). Download: admin `generate` always returns `downloadUrl: null` (129) and the wizard preview has no «download PDF»; the only real file download is the company-surface `GET /company/me/reports/{key}/download` (CrossController.php:112 + ExportService.php:734) which the admin Reports-Manager SPA does not have access to (route is under `company/me`, roles company-*).

## 6. FE wiring notes

- **Canonical vs alias paths**: `/company/me/reports` and `/company/me/reports/{key}/download` are canonical; `/company/me/procurement/reports*` (routes/api.php:794-795) are SPA-prefix aliases — FE should call the canonical pair. Admin catalog lives at `/admin/reports/catalog` (do not confuse with the company card list).
- **Report keys enum** (catalog, ReportController.php:98-106) with Arabic labels verbatim: `pl` «الأرباح والخسائر», `sales-channel` «المبيعات حسب القناة», `smart-compare` «المقارنة الذكية», `profit-cash` «الربح والنقدية», `breakeven` «نقطة التعادل», `op-profit` «ربح التشغيل», `menu-eng` «هندسة القائمة»; `category: core|specialized` drives the Admin Reports page grouping.
- **Sales-channel labels** (ReportService.php:119): `cash` «نقدي», `bank` «شبكة/بنك», `delivery` «تطبيقات التوصيل» (this is the aggregator bucket), `unclassified` «غير مصنف».
- **P&L line labels** (ReportService.php:86-90): «الإيرادات», «تكلفة البضاعة», «مصاريف تشغيلية», «الهدر», «صافي الربح». `profit-cash` note: «الفرق بين الربح المحاسبي والنقدية الفعلية».
- **Money is integer halalas** everywhere (NFR-5) — FE divides by 100 and formats `ar-SA` client-side. Margin fields are pre-rounded floats (`grossMarginPct`, `netMarginPct`).
- **Builder field labels** come from the API (`labelAr`/`labelEn` in `fields`) — never hardcode; unknown keys are rejected 422 with `حقل غير معروف`.
- **Download contract**: `GET /company/me/reports/{key}/download?format=pdf|xlsx` streams a binary (no JSON envelope); `format=json` (default) returns the enveloped payload — FE must branch on format. Screen mapping: ACC-10 «التقارير» file cards and HEAD-7 financial-report cards both consume #23/#24; the Admin 4-step wizard consumes #3/#5/#6/#4/#7 (periods → upload → preview → send → status).
- **Distribution status screen**: `owner`/`email` in status rows come from `AsabBrand.owner/owner_email`; `viewed` is currently always false (see T15.5) — FE should not promise read receipts until that task lands.
- Send today records channels as an array (`["email","inApp"]`); after T15.3 the body gains `method`, `format`, `coverMessage` — FE doc must version this.
