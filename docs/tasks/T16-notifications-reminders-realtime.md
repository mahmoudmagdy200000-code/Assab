2. **Any broadcasting configured? — YES (real, not stub).** Pusher driver active in `.env` (BROADCAST_CONNECTION=pusher, PUSHER_APP_* set), `pusher/pusher-php-server ^7.2` installed, `routes/channels.php` registered via `bootstrap/app.php:17` with `asab`-guard tenant-checked authorizers for all spec channels, `RealtimeBroadcaster` emits 30+ event types fail-safe. 3. **Does the reminder-rules engine execute, or CRUD-only? — CRUD-only.** `AutoReminderRule` is referenced exclusively by `Accountant/ReminderController` and its own model; no console command, job, or schedule evaluates `trigger_hour`/`repeat_hours`; consequently `asab_reminders` has **no producer anywhere** (its list endpoint #13 always returns empty), and `send/bulk-send` only flip statuses without delivering anything (ReminderController.php:121-151).

## 6. FE wiring notes

- **Canonical vs alias paths**: `/reminders/rules` (+ `/{id}`, `/{id}/toggle`) is canonical; `/accountant/reminder-rules` POST/PATCH (routes/api.php:403-404) are doc-conformance aliases — FE uses canonical. Shared bell uses `POST /notifications/{id}/read` + `POST /notifications/read-all`; the company surface uses `PATCH /company/me/notifications/{id}/read` + `POST /company/me/notifications/mark-all-read` — same handlers, different verbs/paths; document both, FE picks per surface.
- **Broadcast body aliases**: canonical `messageAr` + `audience` (`all-branch-managers|all-accountants|all-suppliers|specific-branches`); `message` + `target` (`"all"` or a branchId) are accepted aliases (ReminderController.php:28-50) — FE should send canonical.
- **Reminder status enum** (asab_reminders): `not_sent` / `sent` / `responded`; summary meta `{notSent, sent, responded, totalMissing}` (AccountantController.php:126-131). Personal reminder priority enum: `high|medium|low`; head reminder `type`: `urgent|report|finance|team` with server-provided icons 🔴/📊/💰/👥 and `timeAr` (Arabic time-ago) — render verbatim (PersonalReminderController.php:92-97).
- **Notification item shape**: `{id, type, title, body, link, refType, refId, readAt, createdAt}` — titles are Arabic verbatim from the backend, e.g. «سجل جديد بانتظار المراجعة», «عملية بانتظار الاعتماد النهائي», «عمليتك مرفوضة», «تم اعتماد عمليتك نهائياً», «طلب شراء جديد من فرع», «اشتراك على وشك الانتهاء», «تم إرسال التقرير». Bell counter = `meta.unreadCount` on the list endpoint (polling fallback) + live increment on `notification.new`.
- **Realtime channels** (Echo, `private-` prefix added by transport; auth via `asab` guard): `notifications.user.{userId}` → `notification.new`; `operations.company.{companyId}` → `operation.created|operation.status_changed|approval.pending|module.changed|branch.created|…`; `operations.brand.{brandId}` → `operation.status_changed|shift.opened|shift.closed|inventory.variance_allocated`; `reminders.branch.{branchId}` → `reminder.responded|inventory.flag_sent|shift.opened|shift.closed|asset.confirmation_needed`; `chat.session.{id}` → `message.new|agent.joined|session.closed`. Pusher cluster `mt1`; key from env. FE must implement polling fallback (NFR-12) using #1's `unreadCount`.
- **Quirk**: `notifications/preferences` exists at three paths (`/notifications/preferences`, `/admin/notifications/preferences`) because the platform admin has no companyId for `/company/me/*` (routes/api.php:205-208) — FE doc must map surface→path.
- **Do not promise**: email/WhatsApp/SMS notification delivery, auto-reminder execution, reminder-due alerts, or head notifications for non-approve accountant actions — all pending tasks above; the FE should feature-flag those UI affordances until T16.2–T16.6 land.
