## 2. Answers to critical checks

1. **Employee settle-balance («تسوية الرصيد») endpoint — exists?** **No.** Only the *custody* settle exists (`POST company/me/cash-custody/{id}/settle`, `AccountantCompanyController.php:417`). A repo-wide grep for `settle`/`تسوية` in `Modules/Admin/app` hits only custody code (`AccountantCompanyController.php:417–429`, `CashCustodyController.php:54–67`, `ExportService.php:318`). There is no `employees/{id}/settle-balance` route in `Modules/Admin/routes/api.php` (employee routes are exactly lines 381–383, 677–679). ACC-7.3 is unimplemented → task T09.5.

2. **Replenish/تعزيز عهدة endpoint — dedicated or covered by addTransaction?** **Partially covered, wrong surface/role.** `Accountant\CashCustodyController@addTransaction` (`CashCustodyController.php:69–100`) with `txnType=credit` increments custody `amount` — the replenish semantics — and the platform `/accountant` prefix admits head (`asab.role:accountant,head`, routes/api.php:341). But (a) the **company surface has no POST transactions route** and its custody routes are `asab.role:accountant` only (routes/api.php:614), locking the head out where HEAD-4 says the head *owns* replenish; (b) there is no treasury (الخزينة) source marker, no min-threshold (5,000) context, and no status recompute after the top-up. No dedicated `replenish` endpoint exists anywhere.

3. **Movement categories enum complete?** **No — it doesn't exist at all.** `asab_employee_movements` has no `category` and no `ref` column (migration `2026_06_05_000001_create_asab_ops_detail_tables.php:77–87`; fillable in `EmployeeMovement.php:14–16`). `addMovement` validates only `movementType/amount/description/date` (`EmployeeController.php:64–69`). System writers post free-text descriptions instead of categories: `'تحميل فرق كاش — …'` (`SalesVarianceService.php:49`) and `'تحميل فرق جرد يومي — …'` (`InventoryReconciliationService.php:124`). None of the 8 SRS categories (فرق مبيعات/تسوية/نقص إيصالات/سلفة/مكافأة/غياب/خصم هدر/خصم فرق كاش) or SAL-/ADV-/DED- refs are representable.

4. **Auto-salary-deduction rule — implemented, scheduled, or UI banner?** **Not implemented and not scheduled.** No scheduled command touches salaries/employees/custody (`bootstrap/app.php` — zero matches for salary/payroll/employee/custody). The only materialization is the payroll export netting movements against `monthly_salary` (`ExportService.php:283–304`) — and that netting is buggy (subtracts credits, see row 7). **Documented decision for v1:** the rule ships as (a) an FE banner derived from a negative `balance` in the statement payload plus an explicit `autoDeductFromSalary` flag returned by the statement endpoint, and (b) the corrected payroll-export netting (debits reduce net, credits increase it). An automated monthly job that posts `SAL-` deduction movements is **deferred** (no salary-run exists in ASAB v1) — recorded in T09.8.

5. **Custody status derivation vs min_alert?** **Neither exists.** `asab_cash_custody` has **no `min_alert` column** (migration `2026_06_05_...php:89–102`; SRS §4.5 default 5,000 SAR) and `status` is a stored string defaulting to `'active'` (migration line 99) that no code ever recomputes — the SRS enum is `normal طبيعي | low منخفض | critical حرج`. The index filters on the stored value (`CashCustodyController.php:25–27`) and the summary's near-depletion uses a hardcoded `remaining < 50000` halalas (= 500 SAR) (`CashCustodyController.php:47`) — numerically the ACC-8.1 KPI, but disconnected from `min_alert`/HEAD-4's 5,000 threshold. `settleCustody`/`addTransaction` mutate balances without touching status.

## 6. FE wiring notes

- **Units:** every money field is integer **halalas** (`amountHalalas`, `balanceHalalas`…). The platform-surface accountant endpoints currently name it bare `amount` — same unit; the FE doc must flag both spellings until harmonized.
- **Canonical paths:** company SPA uses `/company/me/...`. `GET company/me/employees/{id}/movements` is the doc-conformance alias of the platform `GET accountant/employees/{id}/statement` (identical handler/payload) — **canonical for the portal = `/company/me/employees/{id}/movements`**; the `/accountant/...` twin serves the platform surface. Same pattern for `employees` and `cash-custody` lists.
- **Enums (key + Arabic label, render verbatim):**
  - Movement category: `sales_variance «فرق مبيعات»`, `settlement «تسوية»`, `receipts_shortage «نقص إيصالات»`, `advance «سلفة»`, `bonus «مكافأة»`, `absence «غياب»`, `waste_deduction «خصم هدر»`, `cash_gap_deduction «خصم فرق كاش»`.
