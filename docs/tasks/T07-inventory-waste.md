## 2. Answers to critical checks

1. **Daily-list save triggers instant push to branch-manager app? — NO.** `saveDailyList` (Modules/Admin/app/Http/Controllers/Accountant/InventoryController.php:223–242) deletes+recreates `asab_branch_inventory_lists` rows and returns a fabricated `pushedAt` timestamp — it never calls `RealtimeBroadcaster` or `NotificationService`. The broadcaster method exists (`inventoryFlagSent`, RealtimeBroadcaster.php:283–286, Pusher channel `reminders.branch.{branchId}`) but is only invoked from `storeCatalog` (InventoryController.php:201) and `inventorySendNotification` (AccountantCompanyController.php:150). There is no FCM/device push anywhere in Modules/Admin. The mobile side only sees the new list on its next pull of `GET /v1/branch/inventory-items` (BranchDashboardController.php:154–183, which does read `BranchInventoryList` — the data bridge itself works). SRS ACC-4.5 «حفظ وتحديث التطبيق فوراً» + MOB-1.2 unmet.
2. **Monthly compare returns prev/curr/% change + anomaly thresholds? — NO.** `index` (InventoryController.php:22–57) returns each branch's *latest* operation payload only; `$type = $request->query('type','monthly')` at line 25 is dead — never used in the query. No previous-month lookup, no `% change`, no server-side red <−30% / green >+30% chip data, no >50% anomaly rule; `anomalyCount` (line 41) merely counts client-supplied `isAnomaly` flags in the uploaded payload (`OperationFactory::createFromUpload` stores `$request->all()` verbatim, BranchDashboardController.php:64). The BR-08 formula exists only in the legacy mobile module (Modules/Inventory `MonthlyInventoryController@comparison`).
3. **Waste allocation reuses sales-variance validation and posts خصم هدر on approve? — NO on both halves.** (a) `WasteController::allocations` (WasteController.php:70–84) validates only `empAllocs => required|array` and stores whatever arrives — compare `SalesVarianceService::assign` (SalesVarianceService.php:23–79) which enforces sum == variance (422 «يجب أن يساوي مجموع التخصيصات قيمة الفارق»), resolves each employee within op company+branch (`resolveEmployee`, 82–93), and posts `EmployeeMovement` debits in one transaction. (b) `approve`/`bulkApprove` delegate to the module-agnostic `OperationService::approve` (OperationService.php:23–48) which only flips status + audit step + notifies head; grep for `خصم هدر` across Modules/ returns zero hits — approved employee-responsibility waste never reaches the Employee Account ledger (SRS ACC-5.3 unmet).
4. **Daily equation فتح+مشتريات−مبيعات±تحويلات=إغلاق implemented in dailyReconciliation? — NO.** `InventoryReconciliationService::snapshot` (InventoryReconciliationService.php:27–83) computes a two-term variance (`expectedQty − actualQty`, % vs expected, 5% `FLAG_PCT` threshold, value via `unit_price`). There are no opening/received/consumed/waste/transfers columns, no per-line equation match check, no min-level or stock status (حرج/منخفض/طبيعي), and no «اعتماد الجرد» approve action specific to the daily table (only the generic operations pipeline). Same two-term math is reused by the Excel export (ExportService.php:150–177).

## 3. Gaps

1. **ACC-4.5 / MOB-1.2 — instant push on daily-list save missing.** `saveDailyList` persists but never notifies; `pushedAt` in the response is untruthful. The «حفظ وتحديث التطبيق فوراً» → «تم الحفظ والتزامن» flow is the dashboard→mobile bridge headline; without it the branch manager doesn't know his count list changed.
2. **ACC-4.4 — monthly compare + % chips + flag-anomaly detection missing.** No prev-month vs curr-month per item, no % change chip data (red <−30% / green >+30%), no server-side >50% swing alert (ACC-4.2 company KPI). FE cannot render the monthly table from `index` as-is; anomaly logic currently trusts the uploading device.
3. **ACC-5.3 — approved employee waste charges never post «خصم هدر» debits.** `empAllocs` are stored dead in the payload; approve does not create `EmployeeMovement` rows, so ACC-7.4's "waste charges" source and the ACC-5.1 «منه على موظفين» KPI can never be true. Financial correctness gap — the whole point of the responsibility toggle.
4. **ACC-5.3 — waste allocation validation is a stub.** Any array passes; unknown employees, negative or over-value amounts accepted. Sales variance already has the right validation (sum==variance, employee ∈ branch) — SRS says "same component as sales shortfall".
5. **ACC-4.3 — daily equation table not implemented.** Reconciliation returns expected/actual variance only; the formula banner columns (فتح، +مشتريات، −مبيعات/استهلاك، −هدر، ±تحويلات، إغلاق فعلي)، per-line match, min level and stock status (حرج/منخفض/طبيعي) have no source endpoint.
6. **Daily variance re-allocation double-charges employees.** `InventoryReconciliationService::allocate` posts new `EmployeeMovement` debits on every call for the same op+date+item without reversing the previous ones, while overwriting the payload record — repeat saves silently multiply debits. Accountant group also lacks `asab.idempotency` middleware (company group has it), so FE retries double-post too.
7. **Branch-confirmation key mismatch.** `inventoryMarkConfirmed` writes `payload.isConfirmed` (AccountantCompanyController.php:164) but `index` derives `branchConfirmed` from `payload.branchReconfirmedAt` (InventoryController.php:43, set only by branch-side `reconfirmInventory`, BranchDashboardController.php:307–318). Accountant-recorded «أكّده الفرع» confirmations are invisible in the list.
8. **ACC-5.1/5.2 — waste list under-serves the screen.** Rows lack date, brand, «منه على موظفين» amount; KPIs pending-review/approved-this-month/total-losses/charged-to-employees absent; no search; unbounded collection (guardrail: paginate or cap).
9. **ACC-4.4 accountant-surface «إرسال» sends nothing; company-surface send is realtime-only.** `sendConfirmation` writes a payload flag with no notification at all; `inventorySendNotification` emits a transient Pusher event with no durable `AsabNotification`, so an offline branch manager never learns of flagged items (also MOB-1.3).
10. **ACC-4.5 — catalog search (ar/en) missing** on `catalog` (only brand/category/type filters), needed for the item-selection screen.
11. **ACC-4.6 — no accountant-surface exports**; Excel lives only under `/company/me/*`. Additionally `ExportService::waste` skips `scopeToAssignedBranches` (assigned-branch accountants can export the whole company's waste) — tighten while touching.

## 6. FE wiring notes

- **Two surfaces, one handler set.** Accountant SPA paths (`/v1/accountant/...`) and company-portal paths (`/v1/company/me/...`) mostly share controllers. Canonical-vs-alias map the FE doc must carry:
  - `POST .../inventory/branches/{id}/flag-items` (company, L646) is canonical; `POST .../flagged-items` (L655) is a doc-conformance alias. Accountant surface uses `POST .../items/flag` (L358).
  - `POST .../inventory/branches/{id}/mark-confirmed` (L648) is canonical; `POST .../confirm` (L654) is the alias.
  - Body field `itemIndices` is canonical; `itemIndexes` accepted as alias (InventoryController.php:77–79).
  - Daily list: accountant `GET/PUT /v1/accountant/inventory/branches/{id}/daily-list` ≡ company `GET/PUT /v1/company/me/branches/{id}/inventory-list`.
  - Exports exist today only under `/company/me/inventory/export` and `/company/me/waste/export` (`?format=xlsx|csv`, binary response — not the JSON envelope).
