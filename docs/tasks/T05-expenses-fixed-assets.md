## ✅ Delivery notes (what shipped vs the plan)

All 13 tasks landed. Deviations and design calls worth flagging for review:

- **T05.1** — the `invoices[]` contract lives in a new `ExpenseInvoiceService`; VAT is split by **division** (`round(incl × 100/115)`), one rounding site, so `preTax+vat === incl` for every row. Invoices may carry their own `vatHalalas` (zero-rated / legacy) and are then **not** re-derived. Legacy single-invoice payloads (root-level `invNum/vendor/verified`) auto-fold to a one-row `invoices[]` on read — no data migration.
- **T05.2** — توثيق stamps `invoices[i]`; the payload-root `verified` flag is kept in sync as "all invoices verified" so `ExportService` column «موثّقة» still reads true. `invoiceIndex` defaults to 0 for the single-invoice case.
- **T05.3** — `matchStatus` is derived on read from attachments + an accountant-entered `documentAmountHalalas`: no docs → `missing`, doc amount ≠ entered → `mismatch`, else `matched`. New review endpoint `PATCH …/invoices/{index}` records the document side and returns the ACC-2.3 side-by-side rows + delta note.
- **T05.4** — `AssetDraftService.convert()` captures `{invoiceId}`+`invoiceIndex`, resolves the expenses op tenant+branch-scoped, throws `409 INVOICE_ALREADY_CONVERTED`, derives the draft value from the invoice **pre-tax** amount, stamps `expense_op_id`+snapshot, and flips the invoice to `convertedToAsset` with `assetDraftId` — one transaction. Target branches are each `assertBranchAssigned`.
- **T05.6** — the draft lifecycle guard is a single `assertOpen()` in the service (409 confirmed/discarded), re-checked under `lockForUpdate()` inside the confirm transaction so two racing confirms can't both mint assets.
- **T05.8** — new `AssetSequence` allocator: per-company `FA-000N` read across soft-deletes, composite unique `(company_id, public_id)`, retry-on-collision. Store **and** import now share it (padding unified to 4). Extracted the driver-agnostic unique-violation check to `Support\UniqueViolation` (also adopted by `OperationSequence`).
- **T05.11** — bridge via `ExpenseBridgeService` + `SyncLegacyExpenseOperation` listener on `ExpenseSubmittedEvent`/`ExpenseApprovedEvent`. Idempotent on `(source_module='expense', source_id)`; **stops overwriting once the accountant has acted** (status ≠ pending); no-op for non-ASAB branches.
- **Bonus correctness fix (out of audit scope):** `TenantBranchResolver` memoized its branch list on the **first** context and served it to every later caller regardless of input — invisible under one-request-per-process, but a queue worker/console loop over tenants would leak branches across companies. Memo is now keyed on a context fingerprint. Surfaced by the two-company asset test.
- **New route:** `GET /company/me/operations/{id}` was missing on the company surface (only the platform surface had `show`), so the expenses statement block was unreachable from the company SPA — added, declared after the literal `operations/export` so it can't shadow it.
- **Not built (deferred, matches SRS scope):** the `assets/import` template download stays skipped per the meeting note ("employee upload template may be skipped to avoid confusion" — same rationale applies); depreciation is straight-line only (no declining-balance), which is all §4.2 specifies.

## 2. Answers to critical checks

1. **Expense statement payload returns invoices[] with pre-tax/VAT/incl-tax fields?** **No — not server-guaranteed.** The payload is pass-through: `$payload = $request->all()` at upload (Modules/Admin/app/Http/Controllers/Branch/BranchDashboardController.php:64), and `show` returns `$data['payload'] = $op->payload` raw (Modules/Admin/app/Http/Controllers/Operations/OperationController.php:50). No code in Modules/Admin computes `amount/1.15`, VAT 15% or incl-tax for expenses (grep `preTax|vat15|1.15` → no expense hits; the only depreciation math is ExportService.php:455-456). If the FE sends `invoices[]` it round-trips; otherwise it doesn't exist. ❌ build (task T05.1).

2. **Invoice-match status (matched/mismatch/missing) computed or stored?** **No.** The only match field is operation-level `asab_operations.match` with values `exact|review|diff` (`OperationFactory.php:37` hardcodes `'exact'` on upload; seeded values at AsabOperationSeeder.php:29-36). No `matchStatus`/`match_status` per invoice anywhere (grep confirmed). The SRS enum matched/mismatch/missing exists nowhere. ❌ build (task T05.3).

3. **Draft stores useful_life + annual depreciation = value/years?** **Half.** `asab_asset_drafts.useful_life_months` exists (migration 2026_06_04_000001:60) and `convertToAsset` writes it (AccountantController.php:300). But annual depreciation is neither computed nor stored for drafts, and `presentDraft` (AssetController.php:205-218) doesn't even return `usefulLifeMonths` — the FE cannot render the wizard step-2 summary (value pre-tax ÷ years) from the API. `min:1` validation instead of the 24|36|48|60|72|84 enum (AccountantController.php:282). 🟡 (tasks T05.4/T05.5).

4. **Converted invoice flagged so it cannot convert twice?** **No.** `convertToAsset` never captures the route param: `function () use ($request, $rt)` (AccountantController.php:278) — `$invoiceId` is dead. No expense-operation lookup, no tenant/ownership validation of the path param (zero-trust violation), no `convertedToAsset`/«محوّل» stamp, `expense_op_id` never written (AssetDraft.php:15 has it fillable; controller omits it). Every call mints a new draft. Compounding: `findDraft` has no `status='draft'` filter (AssetController.php:161-172), so re-POSTing confirm on a confirmed draft **duplicates the created assets**. ❌ (tasks T05.4, T05.6).

5. **Assets list filters (search, category pills) + edit fields (status/value/location)?** **Partial.** Filters: only `status` and `branchId` (AssetController.php:22-27) — no `search`, no `category`, and no pagination (unbounded `->get()`, :28). Edit: `PATCH company/me/assets/{id}` supports `status`, `bookValue` (value), `branchId` (location) plus name/category/custodian/note (AccountantCompanyController.php:176-191) — but `status` accepts any ≤24-char string; the SRS enum `active نشط | maintenance صيانة | retired مُهلك` is not enforced, and the codebase's own status vocabulary is the confirmation-workflow set (`pending_branch/pending_accountant/confirmed` + `active` from import). 🟡 (task T05.7).

## 3. Gaps

1. **ACC-2.2 — invoices[] payload contract with VAT math** → no server-side validation or computation of pre-tax (amount/1.15), VAT 15%, incl-tax per invoice → FE must invent math client-side; ERP/export numbers cannot be trusted; multi-invoice statements have no canonical shape.
2. **ACC-2.2 — per-invoice توثيق** → `verified` stamped at operation payload root, not on `invoices[i]` → for multi-invoice statements the toggle and badge «✅ كل الفواتير موثّقة» are unimplementable; export column «موثّقة: نعم/لا» (ExportService.php:396) reads the same root flag.
3. **ACC-2.1/ACC-2.3 — invoice-match enum matched/mismatch/missing** → not computed or stored → KPI "pending (matched/mismatch/missing split)" and review-modal mismatch delta «⚠ فرق: 200 ر.س عن الفاتورة الأصلية» / missing-invoice state have no data source.
4. **ACC-2.3 — review modal side-by-side** → no endpoint returns entered-data vs attached-invoice-data comparison → modal cannot be wired.
5. **ACC-2.4 — convert-to-asset linkage & idempotency** → `$invoiceId` ignored, no ownership check, no «محوّل» flag, no `expense_op_id`, amount not derived pre-tax → invoice can be converted unlimited times; drafts orphaned from their source invoice; unvalidated path param is a zero-trust violation.
6. **ACC-2.4 — useful life enum 24|36|48|60|72|84 + annual depreciation = value ÷ years** → validated `min:1`; annual depreciation never computed/returned → wizard step 2 summary impossible from API.
7. **ACC-2.6 — drafts panel fields** → `presentDraft` omits inv_num, vendor, desc, expense branch/date, useful_life_months → panel can't render SRS columns.
8. **§4.2 — asset status enum (active نشط | maintenance صيانة | retired مُهلك)** → not enforced anywhere; register mixes workflow statuses (`pending_branch/pending_accountant/confirmed`) with lifecycle statuses (`active`) → filters and the FE status pills have no stable enum.
9. **§4.2 — serial + purchase_date** → no `serial` column in `asab_assets`; store/update don't accept `purchaseDate`/`serial` → register incomplete vs SRS field list.
10. **§4.2 — categories lookup** → static list missing «صيانة وإنشاءات»; labels «أثاث»/«أجهزة إلكترونية» differ from SRS «أثاث ومفروشات»/«تقنية وأجهزة» → category pills won't match seeded/imported data.
11. **List hygiene** → `GET assets` unpaginated + no search/category filter → violates master-plan cross-cutting rule and memory-cap guardrail.
12. **Correctness — `public_id` generation** → per-tenant counter (`Asset::count()+1`, tenant-scoped via BelongsToTenant) against a globally-unique column → second company creating its first asset collides with `FA-001` (500 from unique violation); also a read-then-write race. Import uses a different pad (`FA-0001`).
13. **Isolation consistency — assets export** → `ExportService.assets` scopes by `company_id` only, ignoring the accountant's assigned-branch scope used by the list endpoint → branch-restricted accountant can exfiltrate the full company register via export.
14. **Two-worlds bridge (memory: asab-two-worlds-architecture)** → mobile-app expenses in `Modules/Expense` (with real per-invoice tax fields) never become `asab_operations` rows → the dashboard accountant never sees legacy-submitted expense statements; `source_module/source_id` unused for expenses.

## 6. FE wiring notes

- **Canonical paths**: the company SPA must use `POST company/me/expense-invoices/{id}/convert-to-asset-draft` (canonical) — `accountant/expense-invoices/{id}/convert-to-asset` is the platform-surface twin of the same handler. Draft discard: company surface uses `POST .../asset-drafts/{id}/discard`; accountant surface uses `DELETE .../asset-drafts/{id}` — same handler; document POST as canonical for the company SPA.
- **Aliases**: asset create accepts `cost` (canonical) or `priceHalalas`; asset update accepts `bookValue` (canonical) or `bookValueHalalas`. Responses echo both. All money is **integer halalas**.
- **Enums (key + Arabic label, verbatim UI)**:
  - Draft status: `draft` «في انتظار التأكيد» · `confirmed` «مؤكد» · `discarded` (discarded drafts are hidden from the panel).
  - Asset lifecycle (SRS, post-T05.7): `active` «نشط» · `maintenance` «صيانة» · `retired` «مُهلك»; workflow statuses also appear today: `pending_branch`, `pending_accountant`, `confirmed`.
  - Invoice match (post-T05.3): `matched` «مطابقة» · `mismatch` «غير مطابقة» · `missing` «مفقودة»; badge when all verified: «✅ كل الفواتير موثّقة»; converted marker: «محوّل».
  - Asset categories (post-T05.10): `kitchen` «معدات مطبخ» · `tech` «تقنية وأجهزة» · `furniture` «أثاث ومفروشات» · `vehicles` «مركبات» · `construction` «صيانة وإنشاءات» · `other` «أخرى» (today's lookup differs — see row 19).
- **VAT display math** (ACC-2.2): pre-tax = amount/1.15, VAT = 15%; until T05.1 lands the FE receives whatever the branch uploaded — after T05.1 use the server's `preTaxHalalas/vat15Halalas/inclTaxHalalas` and never recompute.
