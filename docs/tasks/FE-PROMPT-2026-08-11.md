# برومبت للفرونت إند — تحديثات الباك إند حتى 2026-08-11

انسخ هذا الملف كما هو إلى فريق الفرونت (أو إلى مساعد الكود عندهم). كل الحقول
المذكورة **موجودة على السيرفر** بعد النشر الأخير، ولا يوجد أي حقل قديم محذوف —
الإضافات فقط.

---

## السياق

الباك إند أصلح 4 مجموعات أخطاء ظهرت في الاختبار الميداني. بعضها يحتاج تعديلاً في
الفرونت، وبعضها يعمل تلقائياً. المطلوب منكم: البنود المعلَّمة **[FE]**.

---

## 1) موديول المخزون عند المحاسب — الأصناف صارت «أصناف المشتريات»

### [FE] لا حاجة لتمرير `type` بعد الآن

`GET /api/v1/accountant/inventory/catalog?brandId={id}` صار **افتراضه
`raw_material`** (أصناف المشتريات / المواد الخام) — لأن الفرع يجرد المواد الخام لا
أصناف المنيو. أي `type` غير معروف يرجع لأصناف المشتريات، لا لقائمة فارغة.

```jsonc
// GET /accountant/inventory/catalog?brandId=…&type=raw_material|sales_item|all
{
  "type": "raw_material",
  "categories": ["ألبان", "زيوت", "لحوم"],     // تصنيفات النوع المعروض فقط
  "items": [
    { "id": "…", "name": "صدور دجاج", "cat": "لحوم", "unit": "كجم",
      "type": "raw_material", "code": "RM-002" }
  ],
  "total": 8,
  "counts": { "salesItem": 22, "rawMaterial": 8, "all": 30 }
}
```

**المطلوب:**
- شاشة «تحديد أصناف الجرد»: لا تمرر `type` (أو مرر `raw_material` صراحة).
- اعرض العدد من `counts` لا من طول `items` — وإن أردت تبويبين استخدم `type=all`.
- **إن كانت `counts.rawMaterial === 0`** فاعرض رسالة «لم يُرفع ملف أصناف
  المشتريات لهذه العلامة» — الشاشة الفارغة هنا صحيحة وسببها الرفع لا الكود.

### [FE] إضافة صنف من هذه الشاشة

`POST /api/v1/accountant/inventory/catalog` ينشئ الصنف كـ`raw_material` افتراضياً
ويقبل `type` اختياريًا، ويرجّع `type` في الرد. إن كان لديكم زر «إضافة صنف مبيعات»
مرروا `"type": "sales_item"`.

### [FE] حفظ قائمة الجرد اليومي — حقل جديد يجب عرضه

```jsonc
// PUT /api/v1/accountant/inventory/branches/{branchId}/daily-list  { items:[catalogItemId…] }
{
  "savedCount": 8,
  "appListCount": 8,        // ما وصل فعلاً لورقة جرد التطبيق
  "newMobileItems": 2,
  "appListError": null,     // ← جديد: نص الخطأ عند الفشل
  "pushedAt": "…"
}
```

**المطلوب:** لا تعرض «تم الحفظ» الأخضر إلا إذا كان `appListError === null` **و**
`appListCount === savedCount`. غير ذلك اعرض تحذيراً بنص `appListError` — سابقاً كان
الحفظ ينجح ظاهرياً بينما لا يصل للفرع شيء.

### [FE] اسم الفرع بدل الـID

`GET /api/v1/accountant/inventory` (مراجعة الجرد) و`GET /api/v1/accountant/waste`:
كل صف صار يحمل **`branchName`** بجانب `branchId`.

**المطلوب:** اعرض `branchName`، واستخدم `branchId` للفلترة/الروابط فقط.
`branchName` لا يعود `null` أبداً (فرع محذوف يرجع `""`).

## 2) تطبيق الموبايل — أصناف الفرع

هذه إصلاحات سيرفر بلا عمل مطلوب منكم، مذكورة لتفسير ما ستشاهدونه:

| ما كان | ما صار |
| --- | --- |
| شاشة اختيار الأصناف تعرض 15 صنفاً من 30 | الشاشات تُرجع حتى **100** صنف افتراضياً (`per_page` لا يزال يعمل، بحدّ 100) |
| كل صنف بوحدة `(Kg)` | الوحدة المرفوعة فعلاً (`item_unit` يسقط إلى وحدة الصنف قبل أي افتراضي) |
| «الهدر والتالف» فارغ بلا أوامر شراء مغلقة | القائمة تضم أصناف الفرع أيضاً |

### [FE] احترسوا في «الهدر والتالف»

`GET /api/v1/inventory/waste-damage/products-from-closed-orders` يرجّع الآن نصفين:
أصناف الأوامر المغلقة، ثم أصناف الفرع. صفوف النصف الثاني تحمل:

```jsonc
{
  "purchase_order_item_id": "",   // نص فارغ لا null
  "purchase_order_id": "",
  "order_number": "",
  "closed_at": "",
  "expiration_date": "",
  "quantity_ordered": "0.000",    // نصوص decimal كما كانت دائماً
  "quantity_received": "0.000",
  "unit_price": "12.50"
}
```

**المطلوب:** لا شيء إن كنتم تعاملونها كنصوص. **لا تحوّلوا** `quantity_ordered`
وأخواتها إلى أرقام في الـmodel — بقيت نصوصاً كما كانت. ولا يوجد `null` في أي حقل
نصي في هذه القائمة.

### [FE] شفت مدير الفرع — حقل `isFallback`

`isFallback: true` يعني أن الفرع **لم تُضبط شفتاته** وأن `09:00–17:00 / 8h` قيمة
عرض فقط (`shiftCount: 0`).

**المطلوب:** إن كان `isFallback === true` اعرض «لم تُضبط شفتات هذا الفرع» بدل رسم
شفت. الفروع المضبوطة ترجع `isFallback: false` مع بداية الشفت الحقيقية.

## 3) كلمة المرور المُرسلة بالإيميل

كل كلمة مرور تُرسل لمستخدم صارت تستوفي سياسة شاشة الدخول: 12 حرفاً، وتضمن
`a-z` + `A-Z` + `0-9` + أحد `$ & @`، بلا رموز أخرى وبلا أحرف متشابهة (`0/O`,
`1/l/I`).

**[FE] اختياري:** إن كان تحقق كلمة المرور في شاشة تغيير كلمة المرور عندكم أقوى من
`min:8` أخبرونا لنطابق السيرفر معه.

## 4) الشاشات التي سبب فراغها بيانات لا كود

قبل فتح تذكرة على الباك إند، هذه الحالات لها تشخيص جاهز على السيرفر:

| الشاشة الفارغة | السبب المعتاد |
| --- | --- |
| «الجرد اليومي» عند مدير الفرع = 0 صنف | حساب الدخول يفتح فرعاً آخر، أو جدول الجرد معطّل |
| شفتات لا تظهر على أي موبايل | القالب بلا كاشير مسند إليه |
| علامة/مطعم لا يظهر لدى المحاسب | الإسناد لم يصل لشركة العلامة |

فريق الباك إند يشغّل: `asab:inventory-doctor --branch=… | --brand=… | --phone=…`
و`asab:accountant-doctor --email=…` ويعطيكم النتيجة. أرسلوا معنا **معرّف الفرع أو
رقم دخول المستخدم** عند فتح أي تذكرة من هذا النوع.

## قائمة تحقق قبل الإغلاق

- [ ] شاشة تحديد الأصناف تعرض أصناف المشتريات وبعددها الصحيح من `counts`
- [ ] «تم الحفظ» مشروط بـ`appListError === null` و`appListCount === savedCount`
- [ ] `branchName` معروض في مراجعة الجرد والهدر والتالف
- [ ] حقول الكميات في الهدر والتالف تُقرأ كنصوص
- [ ] `isFallback` يمنع رسم شفت وهمي
