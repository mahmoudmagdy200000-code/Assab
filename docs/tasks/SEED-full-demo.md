# FullDemoSeeder — داتا تجريبية واقعية تربط العالمين

> **التشغيل:** `php artisan migrate:fresh --seed` — بيمسح كل الداتا ويبني مجموعة مطاعم كاملة عبر الداش بورد + الموبايل، مربوطة فعليًا.

## حسابات الدخول

### الداش بورد (guard `asab`) — كلها `password`
| الدور | الإيميل | النطاق |
|---|---|---|
| أدمن المنصّة | `admin@nakhat.sa` | كل شيء (بدون شركة) |
| رئيس الحسابات | `head@nakhat.sa` | كل البراندات (scope=all) |
| محاسب برجر بيت | `accountant.burger@nakhat.sa` | براند «برجر بيت» فقط |
| محاسب شاورما | `accountant.shawarma@nakhat.sa` | براند «شاورما الأصيل» فقط |
| مدير المشتريات | `procurement@nakhat.sa` | المنصّة |
| مالك العلامة | `owner@nakhat.sa` | الشركة |

المحاسبان **بيرفعوا تقاريرهم لرئيس الحسابات** (`reports_to_id`).

### الموبايل — كلها `password`
- **مدراء الفروع:** `manager1@nakhat.sa` … `manager9@nakhat.sa`
- **الكاشيرز:** `cashier1001@nakhat.sa` … (لوجين موبايل + مربوطين بالداش بورد بنفس الباسورد)
- **الموردين:** `supplier.meat@nakhat.sa` وغيرهم (لوجين موبايل للمورد)

## الربط بين العالمين (متحقَّق منه)

الداتا **بتمشي end-to-end فعلاً** لأن السيدر بيشغّل نفس خدمات/أحداث الـ runtime، مش بيحشر صفوف:
- **رفع/كتالوج** → `ProcurementCatalogBridgeService` (موردين→`suppliers`، أصناف→`items`+`branch_item`+`supplier_items`) و`ExpenseTaxonomyBridgeService` (تصنيفات→`categories`).
- **كاشير** → `CashierProvisioningService` (لوجين موبايل + `legacy_cashier_id` على الموظف).
- **شيفتات** → `ShiftScheduleBridgeService` (كونفيج→شيفتات موبايل) + إقفال `CashierShift` بيطلق `ShiftEndedEvent` → عملية SHF.
- **مصروفات** → `ExpenseSubmittedEvent` → عملية EXP.
- **وسم الفروع** → `BranchHierarchyLinker`.

**إثبات التوجيه (اللي كان مبلّغ عنه):**
- محاسب برجر يشوف **12** عملية (برانده فقط) · محاسب شاورما يشوف **8** (برانده فقط) · المجموع **20** = تغطية كاملة **بدون تداخل** → كل محاسب يشوف مطاعمه بس.

## ملاحظات
- **`migrate:fresh` بيمسح كل الداتا** — اتأكد إنك على البيئة الصح قبل ما تشغّله.
- **production-safe (faker-free):** السيدر بيعمل الصفوف كلها بـ `::create` مباشر، **مايستخدمش أي `->factory()`** — لأن production بيتثبّت `composer install --no-dev` فـ Faker مش موجود وأي factory بتعمل fatal (`$this->faker` = null). فبيشتغل على السيرفر زي اللوكال بالظبط.
- متحقَّق منه على SQLite؛ على MySQL نفس السلوك (ميجريشن الـ views/procedures بتاعة الكاشير MySQL-only وبتشتغل هناك تلقائيًا؛ السيدر مش معتمد عليها).
- الـ seed بياخد ~50–70 ثانية لأن البريدجات بتشتغل synchronously (بتولّد العمليات فعليًا).
- **طلبات الشراء (PurchaseOrders) مش مزروعة** — عمود `sourceable` polymorphic + enums كتير، والمشتريات ممثّلة أصلاً في الأصناف/`branch_item`/`supplier_items`/الموردين. تنضاف لاحقًا لو محتاجينها.
- عايز داتا أكتر/أقل؟ عدّل `blueprint` (البراندات/المطاعم/الفروع) و`% 2` (الفروع اللي ليها تاريخ تشغيلي) في `FullDemoSeeder`.
