# إصلاح 2026-08-04 — محاسب جديد بلا شركة (WRONG_TENANT)

**الملاحظة:** أُنشئ محاسب جديد «نزار عبد القادر» مسؤول عن فروع جورمية كافيه. عند
فتح حسابه: لا تظهر أي علامة تجارية، ولا يظهر إنشاء شيفتات، والشبكة ترجع:

```json
{ "error": { "code": "WRONG_TENANT", "message": "User is not attached to a company",
             "messageAr": "المستخدم غير مرتبط بشركة" } }
```

---

## السبب

`asab_users.company_id` للمحاسب كان **NULL**. وسطح المحاسب يقرأ الشركة في كل شيء:

- `ResolveTenant` يرفض أي حساب غير إداري بلا شركة على المسارات المستأجَرة → 403 `WRONG_TENANT` على `shifts/configs` و`shifts/live` و`shifts/history` وغيرها.
- ونطاق `BelongsToTenant` يفشل مغلقًا لنفس الحساب → قوائم فارغة («لا توجد علامات تجارية مخصّصة لك بعد»).

ولماذا كان NULL؟ لأن معالج إنشاء المستخدم كان يكتب
`company_id = $data['companyId'] ?? null` فقط — ودور المحاسب يطلب `brands`
(إلزامي) لكن **لم يكن أحد يستنبط الشركة منها**. وشاشة «توزيع المطاعم» كانت تكتب
النطاق (brands/restaurants) دون أن تلمس الشركة، فحتى إسناد جورمية كافيه للمحاسب
لم يكن يُصلح حسابه.

## ما تم

### 1) الإنشاء يستنبط الشركة من العلامات (ويمنع الخلط)

`POST /api/v1/admin/users` بدور `accountant`:

- `brands.*` أصبح مُتحقَّقًا من وجوده (`exists:asab_brands,id`) — معرّف مجهول كان يمر ويُنتج محاسبًا بلا شركة.
- إن لم يُرسل `companyId` → يُستنبط من شركة العلامات المختارة.
- إن أُرسل `companyId` ولم تتبعه العلامات → **422 `BRAND_NOT_IN_COMPANY`** (كان يُقبل: إسناد محاسب شركة إلى علامة شركة أخرى).
- علامات من شركتين مختلفتين → **422 `BRANDS_SPAN_COMPANIES`** (المحاسب يتبع شركة واحدة).

### 2) شاشة «توزيع المطاعم» تُصلح الحساب

`PATCH /api/v1/admin/accountants/{id}/assignments` صار يملأ `company_id` من
العلامات (أو من مطاعم الإسناد) عند إسنادها — **يملأ NULL فقط** ولا ينقل محاسبًا
بين الشركات (عملياته وتقاريره القديمة تحمل الشركة السابقة).

عمليًا: افتح «توزيع المطاعم» → أسند «جورمية كافيه» لنزار → يعمل حسابه فورًا.

### 3) إصلاح الحسابات القائمة

```bash
php artisan asab:repair-user-companies --dry-run   # جدول: المستخدم / الدور / الشركة المستنبطة
php artisan asab:repair-user-companies
```

يستنبط الشركة من النطاق الموجود: العلامات ← المطاعم ← الفروع ← شركة الرئيس الذي
يتبعه. يملأ NULL فقط وعند وضوح شركة واحدة؛ والحسابات الغامضة تُدرج في تحذير
لتُسند يدويًا. حسابات المنصّة (مورد / مدير مشتريات) تُترك كما هي — الـ NULL حالتها
الصحيحة.

### 4) «تابعين لـ undefined» + شرائح العلامة

`GET /api/v1/admin/distribution` كان يرسل `headId` بلا اسم، وبلا علامات المحاسب:

```jsonc
{
  "accountants": [{
    "id": "…", "name": "نزار عبد القادر",
    "headId": "…",
    "headName": "خالد العمري",                                   // ← جديد
    "brands": ["…"],                                              // ← جديد
    "brandsNamed": [{ "id": "…", "name": "جورمية كافيه" }],       // ← جديد
    "brandCount": 1,                                              // ← جديد
    "companyId": "…",                                             // ← جديد
    "needsCompany": false,                                        // ← جديد: true = حساب معطّل
    "restaurantsNamed": [ … ], "modules": [ … ]
  }]
}
```

**للفرونت:** اعرض `headName` بدل الـ id، وشرائح `brandsNamed`، وعلامة تحذير على أي
صف `needsCompany: true` (هذا الحساب لن يفتح أي شاشة حتى تُسند له علامة).
