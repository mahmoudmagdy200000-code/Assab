# ملاحظات 2026-08-03 — ما تم إصلاحه في الباك إند وما يلزم من الفرونت

خمس ملاحظات وصلت على واتساب. ثلاث منها كانت أخطاء باك إند وتم إصلاحها،
واثنتان عرض/CSS في الفرونت والباك إند يرجع البيانات كاملة.

---

## 1. «بعد رفع الأصول الثابتة، حالة الرفع تبقى «لم يُرفع»» — ✅ باك إند

`GET /api/v1/admin/brands/{brandId}/branches/upload-status` كان يجلب فروع
العلامة بـ `branches.asab_brand_id` فقط. الفرع المرتبط بالمطعم
(`asab_restaurant_id`) وعموده `asab_brand_id` فاضي — وهذه الحالة الشائعة —
ما كان يظهر أصلاً، فترجع القائمة **فارغة** ويرسم الجدول كل الصفوف على
القيمة الافتراضية «لم يُرفع» مهما تكرر الرفع.

صار الحل يمرّ على نفس الدالة التي تستخدمها تغذية الكتالوج:
الرابط المباشر **أو** عبر مطاعم العلامة، مع تعبئة العمود الناقص
(backfill) تلقائياً.

**الفرونت:** لا تغيير في الشكل. فقط تأكدوا أن الجدول يقرأ حالته من هذا
النداء (يرجع صفاً لكل فرع مع `fixedAssetsStatus`:
`not_uploaded | done | failed` و`fixedAssetsCount` و`fixedAssetsFailureReason`)
وأن الاستدعاء يُعاد بعد نجاح الرفع.

## 2. «تحميل النموذج مرة أخرى يرجع فارغاً» — ✅ باك إند (جديد)

`GET /api/v1/admin/upload/templates/{type}` صار يقبل معرّف المالك ويحمّل
**البيانات المحفوظة فعلاً** بنفس ترتيب أعمدة القالب:

| النوع | المعامل | المصدر |
|---|---|---|
| `sales-items` / `raw-materials` | `?brandId=` | `asab_inventory_catalog` |
| `suppliers` | `?brandId=` | `asab_suppliers` |
| `fixed-assets` | `?branchId=` (أو `?brandId=` لكل فروعها) | `asab_assets` |
| `employees` | `?restaurantId=` | `asab_employees` |

- بدون معرّف مالك → القالب الفارغ كما كان (لا تغيير كاسر).
- المالك بدون بيانات → القالب الفارغ أيضاً.
- `?withData=0` → القالب الفارغ حتى مع وجود بيانات.
- اسم الملف يصير `{type}-data.xlsx` بدل `{type}-template.xlsx` عند وجود بيانات.
- صفوف «Sample only» في نموذج الأصول تختفي عند وجود بيانات حقيقية.
- المبالغ تُصدَّر بالريال (نفس ما يُقرأ عند الرفع)، والأصول بالتخطيط
  الإنجليزي (`Serial Number … Notes`).

**إعادة الرفع صارت تحديثاً لا تكراراً** — وهذا لازم لأن التحميل صار سطح
تعديل: صنف الكتالوج يُطابَق على (العلامة + النوع + رمز الصنف، أو الاسم إذا
لا يوجد رمز)، والأصل يُطابَق على (الشركة + الفرع + الرقم التسلسلي). الأصل
الذي استلمه الفرع يحتفظ بحالته ولا يرجع إلى `pending_branch`.

**الفرونت:** أضيفوا المعرّف على زر «نموذج» في كل بطاقة/صف:
`/admin/upload/templates/sales-items?brandId={brandId}`,
`/admin/upload/templates/fixed-assets?branchId={branchId}` … إلخ.

## 3. «ملخص البيانات لا يعمل / غير صحيح» — ✅ باك إند

`GET /api/v1/admin/brands/{brandId}/upload-status` كان يحسب `completionPct`
على **أربع** خطوات ويضع `fixed-assets` داخل `shared` — والشاشة أصلاً تعرض
ثلاث بطاقات مشتركة فقط، والأصول تُرفع لكل فرع. لذلك بقيت البطاقة على 3/4
والنسبة على 75% لعلامة رفعت كل المطلوب.

**التغيير (كاسر):**

```jsonc
{
  "shared": { "sales": true, "materials": true, "suppliers": true },  // 3 مفاتيح، بدون fixedAssets
  "brandFixedAssets": false,          // ⭐ جديد — انتقل من shared
  "completionPct": 100,               // الإعداد كله: 3 مشتركة + فرع لكل أصول + مطعم لكل موظفين
  "branchesLinked": 2,
  "summary": {                        // ⭐ جديد — كل بطاقات «ملخص رفع البيانات»
    "shared":              { "done": 3, "total": 3 },
    "branchAssets":        { "done": 2, "total": 2 },
    "restaurantEmployees": { "done": 2, "total": 2 },
    "completionPct": 100
  },
  "uploads": [ /* كما هي */ ]
}
```

**الفرونت:** اربطوا البطاقات الأربع على `summary` مباشرة بدل اشتقاقها:
«بيانات مشتركة» = `summary.shared`، «أصول الفروع» = `summary.branchAssets`،
«موظفي المطاعم» = `summary.restaurantEmployees`، «اكتمال الإعداد» =
`summary.completionPct`.

## 4. «الأسامي غير واضحة في قائمة يرفع تقريره إلى» — ✅ الباك إند أغنى الرد

`GET /api/v1/lookups/users?role=head` كان يرجع `{id, name, role}` و`role`
مفتاح إنجليزي خام، فما عند القائمة شيء تفرّق فيه بين متشابهي الاسم. الرد
الآن:

```json
{ "id": "…", "name": "حسن رشدي", "email": "hasan@…", "role": "head",
  "roleKey": "head", "roleLabel": "رئيس حسابات", "status": "active",
  "label": "حسن رشدي — رئيس حسابات" }
```

ويقبل `&status=active` لاستبعاد الحسابات الموقوفة من القائمة. الاسم الفارغ
(دعوة لم تكتمل) يسقط على البريد بدل خيار فارغ.

**الفرونت:** اعرضوا `label` (أو `name` + `roleLabel`). القصّ في الصورة يبدو
أيضاً عرض عمود/`overflow: hidden` — القيمة تصل كاملة من الباك إند.

## 5. «التاريخ غير صحيح» في الاشتراكات — ✅ باك إند

مشكلتان:

1. الحمولة ما كان فيها تاريخ جاهز للعرض، فطُبع الـ ISO خاماً
   (`2026-09-03T15:55:41+03:00`). أُضيف **`expiresAtDate`** (`YYYY-MM-DD`)
   بجانب `expiresAt` الذي بقي كما هو.
2. `daysLeft` كان يُقرأ من عمود **مخزَّن** لا يحدّثه إلا أمر
   `CheckExpiringSubscriptions`، ولا يلمس إلا الاشتراكات الداخلة في نافذة
   التنبيه — فبقيت بقية البطاقات على الرقم الذي أُنشئت به ولا تنقص. صار
   يُحسب من `expires_at` عند كل قراءة، على حدود اليوم، ولا ينزل تحت الصفر.
   وأُضيف **`isExpired`**.

يشمل ذلك `GET /admin/subscriptions`، `/admin/restaurants/subscriptions`،
بطاقات العلامة في `/admin/brands*` و`/admin/overview` (أضيف لها كذلك
`expiresAt` و`expiresAtDate`).

**الفرونت:** اطبعوا `expiresAtDate`، واستخدموا `isExpired` بدل مقارنة
النص.
